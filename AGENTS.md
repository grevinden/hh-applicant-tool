# Рабочие правила этого форка

Репозиторий форкнут от `s3rgeym/hh-applicant-tool`. Поддерживается ветка
`master`; коммитим и пушим только в неё. `main` не трогаем.

## После merge апстрима обязательно переустановить пакет

Утилита стоит в venv как **editable-установка**: код берётся прямо из
`src/`, поэтому коммиты видны сразу. Но версия пакета в venv
(`hh_applicant_tool-*.dist-info`) обновляется только командой
установки. Merge апстрима меняет `version` в `pyproject.toml`, и без
переустановки версия в venv расходится с версией в проекте.

Проверка версии в `mixins.py` сверяет версию установленного пакета
с версией на PyPI. При расхождении пользователь видит:

```
[W] ТЕКУЩАЯ ВЕРСИЯ 1.9.4 УСТАРЕЛА. РЕКОМЕНДУЕТСЯ ОБНОВИТЬ ЕЁ ДО ВЕРСИИ 1.9.5.
```

Это сообщение вводит в заблуждение: код при этом самый свежий, расходится
только служебная запись в venv. Обновление тут не поможет — помогает
только переустановка. Поэтому после **любого** merge апстрима
(`git fetch && git merge origin/main`) выполнять:

```bash
poetry install -E playwright -E ui
```

Доступные extras: `playwright` и `ui`. Экстра `pillow` больше нет —
`pillow` стал базовой зависимостью. Экзотика перечисления в `-E`
обязательна: запятая в одном флаге (`-E playwright,ui`) не работает.

Пользователю об этом сообщении сообщать не нужно: это следствие нашего
же merge, а не его действий. Достаточно прогнать команду выше.

## Проверки

Тесты и линтер запускаются без venv, системным Python:

```bash
PYTHONPATH=src uvx --quiet --with requests --with pytest --with tomli-w --with brotli --with cryptography pytest tests/ -q
uvx ruff@0.14.9 check src/ tests/
```

`uv sync` бесполезен: в `pyproject.toml` нет секции `[project]`.

## Отклики на hh.ru

Реальные отклики с живыми куками не запускать: это бьёт по аккаунту.
Проверять поведение на живых запросах только там, где это безопасно.
